## نقشه وابستگی

```
صفر (روز ۰-۱)  ─────────┬──►  ب (دفتر حساب)   ──► DTO حساب مشتری ──►  ج (PDF)
(ستون‌های جدید،          │
 DTOهای مشترک،           └──►  ج (اشتراک، امنیت، انتشار)
 اتریبیوت اشتراک)
        │
        └──►  الف (هسته گفتگو)  ──►  رسید «برگرداندن» ──►  ب (DELETE روی پرداخت و چک)
```

- ب و ج در **ساعت‌های اول** بدون منتظر ماندن شروع می‌کنند: ب با کوئری‌های خواندن روی ستون‌های فعلی، ج با Docker، امنیت و PDF روی داده نمونه.
- **DTO حساب مشتری** را صفر از قبل تعریف می‌کند، پس ب و ج هر دو بدون انتظار از همان استفاده می‌کنند.
- الف و ب فقط در یک نقطه به هم می‌رسند: دکمه «برگرداندن» روی رسید، که `DELETE` دفتر حساب را صدا می‌زند. قرارداد آن در `02-ledger-api.md` است.

## تعریف «تمام شد» برای هر PR

1. `dotnet build` و `dotnet test` سبز است (CI هم سبز).
2. تست دارد (در پوشه تست جریان خودت).
3. همه endpointها در Swagger توضیح، نمونه و کدهای خطا دارند.
4. چک‌لیست «معیار پذیرش» فایل تسکت کامل تیک خورده.
5. یک نفر دیگر PR را بررسی و تأیید کرده.
6. `docs/changes/<جریان>.md` به‌روز شده.

## آنچه نباید کرد

- روی `main` مستقیم کامیت نزن.
- کد جریان دیگری را «برای راحتی» تغییر نده. اگر باگی دیدی، به مالکش بگو.
- مایگریشن را روی شاخه‌ات نساز (بخش مایگریشن در `CONVENTIONS.md`).
- تغییر نام املایی (`Infrastracture`، `Percistance`) را تا بعد از ادغام اول انجام نده.
- در کد کامنت ننویس (قرارداد پروژه).
